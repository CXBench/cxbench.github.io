01 / THE RESEARCH QUESTION

A correct destination
can hide a wrong turn.

When an agent completes a task, did it also satisfy the applicable process requirements?

In regulated customer service, a correct final state is only part of the story. An agent may also need to explain rights, provide a required notice, obtain authorization, and avoid unsupported promises. These obligations live in the interaction, not just the final database record.

CXBench evaluates the outcome and the process separately. A run that achieves the requested result but fails the process checks is a false-pass: a failure that outcome-only evaluation would count as success.

FALSE-PASSOutcome ∧ ¬Process

Rule-only and LLM-only scores are diagnostic views. Formal CXBench results use the hybrid verdict.
How submission authority is controlled +

In the default mediated-submit mode, the agent can inspect records, check conditions, issue notices, and prepare a draft. Submission tools are excluded from its actions. The runtime submits only after the customer confirms the required fields and those fields still match the draft.

Draft → Customer confirmation → Runtime submission

This mechanism enforces selected action constraints. Required disclosures, restrictions on promises, and other obligations still need trace-level evaluation. A confirmed, successfully submitted draft can therefore remain a false-pass.

How the benchmark is constructed +

The authors extracted 55 obligations from regulatory materials available through the Legal Information Institute and deduplicated them into 53 rule cards. Industry collaborators contributed scenarios, feedback, rule review, and trace annotations; three senior software-engineering experts reviewed the mappings.

An LLM-assisted pipeline synthesizes candidate tasks from rule cards and registered domain interfaces. Structural checks validate supported tools, rule identifiers, non-empty checklists, and confirmation fields. Semantic review separately examines fidelity to the source obligation. The resulting benchmark has 20 tasks per domain.

New domains supply business states, tools, and requirement mappings while reusing the interaction loop, trace format, submission controls, and evaluation protocol.

06 / READING THE EVIDENCE

What the results support.
Where the limits remain.

SUBMISSION CONTROL

The scoring protocol matters.

For gpt-5.4, the original hybrid protocol reports 20.83% both-pass for mediated submission versus 0.83% for direct submission. Excluding submission-mechanism checks from both grading components gives 20.83% versus 18.33%.

The adjusted difference is −2.50 percentage points (95% bootstrap CI [−10.00, 5.00]; exact McNemar p = 0.677639). This is a rescoring analysis of recorded traces, not a fresh agent or simulator run. The large original gap is scoring-sensitive.

JUDGE SENSITIVITY

Agreement is not accuracy.

On 720 fixed traces from six models, replacing gpt-5.6-sol with gpt-6-astra changes pooled both-pass from 13.89% to 14.72%. Hybrid verdict agreement is 92.22%, with Kendall's τb = 0.9661.

No previously strict pairwise ordering reverses. Shared hard-rule failures can mask semantic-judge disagreement, so this comparison measures consistency between configurations.

EXPERT COMPARISON

Calibration, not held-out validation.

The baseline judge agrees with one expert on 106 of 120 development traces (88.33%). For process pass, precision is 69.70%, recall 85.19%, and F1 76.67%.

These traces come from one agent model and were used in judge development. They do not establish held-out accuracy or inter-rater reliability.

+

Scope of the benchmark. CXBench evaluates requirements encoded in synthetic workflows with a simulated customer. A process verdict is not a legal certification. One retained execution per model–task pair does not measure repeated-run variability; changes in regulations, jurisdictions, or workflow assumptions require renewed review.
